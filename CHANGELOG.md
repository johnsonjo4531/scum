# Changelog

## 0.1.0

- The game logic right now was written for the card game of war can you remove all war related code and change it to be for the scum card game (see design-docs/scum-rules.md for the rules of scum): Rewrote `src/main.rs` from War into Scum per the rule specification. The deck is shuffled and dealt evenly each round (max difference of 1). A play is a group of same-rank cards (single/pair/triple/quad); to beat the current pile a play must match its size exactly and be strictly higher rank; passing is always allowed. When every remaining player passes consecutively after the last successful play, the pile is discarded and the last winner leads again (or the lowest-numbered holder when that winner has gone out). Players who empty their hand are eliminated in finish order; when only one player holds cards the round ends and ranks are assigned King, Queen, Peasants, Vice Scum and Scum. The previous round's Scum starts subsequent rounds; round 1 is started by the holder of the lowest card (suit alphabetical tie-break). Card transfers between rounds are narrated per §5 edge cases before the re-deal. Four players are simulated with a simple heuristic AI and advanced with SPACE (single step) or held SHIFT (auto-play). The package was renamed from `war` to `scum`.
- fix all the errors in this repo: Installed the missing `rustc-codegen-cranelift-preview` component required by `.cargo/config.toml` on the nightly toolchain. Rewrote all UI construction using Bevy 0.19's `bsn!`/`bsn_list!` scene notation, replacing nonexistent APIs (`ImageSourceTemplate`, hand-written system tuples, broken query sorting) with valid scenes and systems. Moved the ignored target-scoped `linker`/`rustflags` keys from `Cargo.toml` into `.cargo/config.toml`. Added integration tests that spawn the real UI scenes and verify dealing, lowest-card lead selection, trick-size/rank beat rules, passing, trick resets (including not leading with an eliminated player), elimination ranking and multi-round flow.
